## 二、Layer B 语义检查独立化

### 问题

`buildSemanticCheckPrompt()` 产出的跨阶段语义检查上下文被追加到 system prompt 末尾。system prompt 定义了 LLM 的"评分 persona"，任何跨阶段上下文在其中都会不可避免地影响四维评分。实测 S6 出现 20 分 gap（100→80），Layer B 的跨阶段信息污染了评分。

### 改动

**文件**：`src/lib/audit/ai-quality.ts`、`src/lib/audit/cross-stage.ts`

1. `buildAuditSystemPrompt()` 不再拼接 Layer B 内容
2. Layer B prompt 移到 user message 末尾，作为独立任务块：
```typescript
if (crossStagePrompt) {
  userMessage += `\n\n---\n\n## ⚠️ 独立任务：跨阶段语义检查（完成四维评分后再处理）\n\n${crossStagePrompt}`;
}
```
3. `buildSemanticCheckPrompt()` 开头从"请在评分时额外检查"改为"请检查语义连贯性，但严格将发现记录在 crossStageSemantics 字段中"
4. 添加 blockquote 隔离警告：`> **⚠️ 四维评分已在上方完成。以下内容仅供独立语义检查，绝对不要因此调整四维评分的任何分数。**`
5. `mergeDecisions()` 新增 `layerBWarningCount` 参数和 `LAYER_B_WARNING_THRESHOLD=1` 常量：当 gate 为 advance 但 Layer B warnings ≥ 1 时，降级为 reoptimize

### 效果

S6 从 20 分 gap（100→80）变为 0 分 gap（100→100）。关键洞察：**system prompt 定义评分 persona，任何评分无关内容放入 system prompt 都会污染评分**。

## 三、评分锚点（Scoring Anchors）策略

### 动机

通用版四维评分使用描述性 focusAreas（例如"消费者定义是否基于决策动机和行为特征"），LLM 对"多具体算 4 分 vs 5 分"判断不一致，导致同模型噪音和跨模型分歧。

### 方案

在 `StageAuditConfig` 中增加可选字段 `scoringAnchors: Partial<Record<AuditDimension, DimensionAnchors>>`，每维度定义 1/3/5 分的可数、可核对标准。

```typescript
interface DimensionAnchors {
  score1: string;  // 1 分标准：描述"差"的样子
  score3: string;  // 3 分标准：≥N 个可数条件
  score5: string;  // 5 分标准：≥M 个更严条件
}
```

`buildAuditSystemPrompt()` 检测到 scoringAnchors 时，在每个维度后渲染 1/3/5 锚点。

### 锚点设计原则

经过 S1 和 S8 v1 的失败教训，总结出有效锚点的条件：

1. **1 分描述"差"的样子**，不是"零个 X"（避免 flash 将所有未达标判 1 分）
2. **3 分和 5 分有明确的 ≥N 条件**，但不过度具体（避免 flash 逐条 checklist）
3. **锚点精度匹配输出质量**：中游输出（~70-80 分）受益最大；偏科输出（某些维强某些维弱）会被锚点放大分歧
4. **简化版 > 复杂版**：S8 v1（每条件 ~60 字）gap 30，v2（每条件 ~30 字）gap 5.0

### 各阶段效果

#### S4 消费者洞察（✅ 保留）

| 指标 | 通用版 | 锚点版 |
|------|:------:|:------:|
| chat 噪音 | 15 | 5 |
| 跨模型 gap | ~10 | 6.3 |
| 维度零波动 | 1/4 | 3/4 |

锚点让 chat 从离散（56-71）收敛到（71-76），flash 从激进（44 block）回归合理（68 reopt）。Gate 仍在阈值边界翻转，属于阈值问题而非锚点问题。

#### S7 视觉策略（✅ 保留）

| 指标 | 通用版 | 锚点版 |
|------|:------:|:------:|
| chat 噪音 | **8** | **0** |
| 跨模型 gap | 2.7 | 9.0 |
| Gate 一致性 | ❌ | ✅ |

噪音从 8 归零是最显著的改善。跨模型 gap 增大了（chat 91 vs flash 100），但都在 advance 区间，Gate 一致。

#### S8 内容规划（✅ 保留 v2）

| 指标 | 通用版 | 锚点 v1 | 锚点 v2 |
|------|:------:|:------:|:------:|
| 跨模型 gap | 8.0 | 30.0 | **5.0** |
| flash 得分 | 86 (adv) | 48 (block) | 73 (reopt) |
| Gate 一致性 | ❌ | ❌ | ✅ |

v1 锚点过于严苛（"所有平台有完整策略类型+频率+角度+KPI"），flash 严格执行导致 block。v2 简化条件后 gap 收敛到 5.0。

#### S1 用户访谈（❌ 回退）

| 指标 | 通用版 | 锚点版 |
|------|:------:|:------:|
| 跨模型 gap | 7.3 | **26.0** |
| flash 得分 | 81 (adv) | 64 (reopt) |
| Gate 一致性 | ✅ | ❌ |

S1 输出"偏科"——故事丰富（S/D 强）但结构化字段为空（confirmedProblems=[]，constraints 全空）。锚点放大了两个模型对这种偏科的容忍度差异，chat 继续慷慨、flash 严格执行扣分。**结论：偏科型输出不适合锚点，锚点会放大分歧**。

#### S2/S3/S5/S6（无需锚点）

这四个阶段通用版本身表现优秀：S2 和 S3 零噪音零 gap，S5 零噪音 gap 3.0，S6 噪音 2 gap 4.7。无需添加锚点。

## 四、阈值调整

### 问题

原始阈值与各阶段实际评分范围不匹配：

| 阶段 | 原阈值 | 实际评分 | 问题 |
|:----:|:------:|:--------:|------|
| S3 | 75/55 | 74 | 卡线下 1 分 |
| S4 | 75/55 | 71-76 | ±1 翻转 |
| S5 | 75/55 | 74-77 | ±1 翻转 |
| S8 | 80/60 | 73-78 | 全部卡线 |

### 改动

| 阶段 | 原阈值 | 新阈值 | 理由 |
|:----:|:------:|:------:|------|
| S1 | 70/50 | 70/50 | 不改，评分远超阈值 |
| S2 | 70/50 | 70/50 | 不改，评分远超阈值 |
| S3 | 75/55 | **70/55** | 下降 5，消除卡线 |
| S4 | 75/55 | **70/55** | 下降 5，消除翻转 |
| S5 | 75/55 | **70/55** | 下降 5，消除翻转 |
| S6 | 80/60 | **75/60** | 下降 5，评分仍远超 |
| S7 | 80/60 | **75/60** | 下降 5，评分仍远超 |
| S8 | 80/60 | **70/55** | 下降 10，匹配锚点后评分 |

### 原则

advance 阈值应该在实际评分范围的下方（留出合理余量），而不是卡在实际评分的中心位置。阈值反映的是"这个阶段的最低可接受标准"，而非"优秀标准"。

## 五、≤2 分保护规则

### 问题

总分可能因为其他维度高分而达到 advance 阈值，但某个关键维度只有 1-2 分。这种"偏科"不应直接通过。

### 改动

**文件**：`src/lib/audit/ai-quality.ts`，gate 决策逻辑中新增：

```typescript
// 任一维度 ≤2 分 → 不允许直接 advance（防止总分达标但关键维度短板）
const hasScore2 = dimensionScores.some((d) => d.score <= 2);

if (hasScore2 && gateRecommendation === "advance") {
  gateRecommendation = "reoptimize";
}
```

原有的 `hasScore1`（≤1 分）已存在，`hasScore2` 扩展了这个保护逻辑到 2 分。

### 适用范围

全阶段通用。不需要特殊配置 — 任何阶段输出中出现维度 ≤2 分，即使总分达标也至少需要 reoptimize。

> *S5 阈值从 75→70 后，之前 74-77 的翻转理论上已消除，未重跑验证。

### 关键经验

1. **锚点不是银弹**：对输出质量均衡的阶段有效（S4/S7/S8），对偏科输出反而放大分歧（S1）
2. **锚点越简单越好**：S8 v1 复杂锚点 gap 30，v2 简化后 gap 5.0
3. **Layer B 不能进 system prompt**：任何评分无关内容放入 system prompt 都会污染评分
4. **阈值应低于实际评分**：阈值卡在实际评分中心会导致每次跑都有 Gate 翻转
5. **≤2 分保护是必要的安全网**：防止总分掩盖维度短板
6. **flash 比 chat 更严格执行锚点**：这既是优势（更忠实于标准）也是风险（过于严格会导致 block）
