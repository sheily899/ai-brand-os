## 4. Part 4: 多模型对比 — deepseek-chat vs deepseek-v4-flash

### 4.1 总分对比

| 案例 | chat μ | flash μ | Δ | Gate 一致 | 判定 |
|:---|---:|---:|---:|:---:|:---:|
| A 慢象咖啡 | 94.0 | 87.8 | 6.2 | 6/8 | ✅ |
| B 快享茶饮 | 52.4 | 43.1 | 9.4 | 6/8 | ⚠️ |
| C YoungLife | 22.0 | 23.1 | 4.1 | 8/8 | ✅ |

### 4.2 排名一致性

| 模型 | A | B | C | 排序 |
|:---|---:|---:|---:|:---|
| chat | 94.0 | 52.4 | 22.0 | A > B > C |
| flash | 87.8 | 43.1 | 23.1 | A > B > C |

**排名一致率: 100%** ✅ — 两模型在不同架构下给出完全相同的质量排序。

### 4.3 结论

- **flash 更保守**: 所有案例平均低 6.6 分
- **中等案例分歧最大**: Case B Δ=9.4 > 阈值 8 ⚠️
- **低质量案例高度一致**: Case C Δ=4.1，Gate 0/8 不一致
- **flash 技术问题**: 多个 "Unexpected end of JSON input" 错误（空响应），fallback→60 分失真。疑似 `responseFormat: json_object` 或 `maxTokens=16384` 在长 prompt 下不兼容

## 7. 问题发现

| # | 问题 | 严重度 | 证据 | 建议 |
|:---|:---|---|:---|:---|
| **P0** | **S6 天花板效应**：高质量案例 S6 μ=100.0 σ=0（3 次独立验证均满分） | Critical | Case A S6 5 次运行全部满分，不同 case（慢象咖啡/香薰品牌）均触发 | score5 锚点增加"需逐字段引用原文交叉验证"标准；或增加 score5+ 区分"卓越中的卓越" |
| **P0** | **S3 Evidence=40% 导致 Case B 全部 Block**：σ=0, μ=32.0 | Critical | 一般质量案例在 S3 被 Evidence 维度拉至 floor | Evidence 40%→35%，block 阈值 55→50 |
| **P1** | **Case B 总分 53.8 低于预期** | Major | S3(32)+S5(37) 两个 Evidence 重权阶段拖累整体 | 调整 S3/S5 权重和 block/reoptimize 阈值 |
| **P1** | **v4-flash JSON 解析失败率高**：空响应导致 fallback 60 分 | Major | Case A 多个 "Unexpected end of JSON input" | 排查 `responseFormat: json_object` 兼容性，增加 maxTokens |
| **P1** | **S7 接近天花板**：Case A μ=99.6 σ=0.8 | Major | 与 S6 类似问题，score5 标准不够严 | 提高 S7 score5 标准 |
| **P2** | **JSON 截断偶发**：chat 模型约 1-2% 调用出现 | Minor | Case B S4 run3, S7 runX 等出现 JSON 解析错误 | 增加 maxTokens 到 4096，或精简 prompt 中重复信息 |
| **P2** | **Case A 均分超预期上限** μ=95.2 | Minor | 阈值预期上限 95 偏紧，但这是系统能力强而非问题 | 将 Case A 预期调整为 [90, 98] 以反映高质量案例的真实天花板 |
