## P1 · S3 Convergence 校验失败率高

- **现象**：5 个案例中 4 个 S3 需要 2-3 次 retry（共 9 次额外 LLM 调用），S1/S2/S4/S6/S7/S8 几乎全部 0 retry
- **根因**：S3 Schema 字段最多且嵌套深（marketOverview/industryTrend/channelAnalysis/categoryStatus/experienceGaps/opportunityDirections），AI 首次输出易遗漏子字段（如 `evidenceLevel`、`currentAlternative`）
- **影响**：每个 retry 额外消耗 ~800 tokens
- **优化建议**：
  1. S3 Convergence Prompt 显式列出所有必填子字段
  2. 或将部分深层必填字段改为 optional + default，降低 schema 严格度

## P1 · 阶段间搜索上下文不延续

- **现象**：`advanceToNextStage()` 的搜索结果仅注入首轮 Opening Message，第 2 轮起 consultation 对话丢失搜索上下文
- **根因**：
  1. `AdvanceResult` 未返回 `searchContext` 字段
  2. batch 脚本 `sendMessage()` 调用未传 `searchContext`
- **影响**：S2/S3/S5/S8 后续轮次 AI 无法引用搜索发现
- **优化建议**：
  1. `AdvanceResult` 增加 `searchContext: string` 字段
  2. batch 脚本 consultation 循环中沿用它

## P2 · S4 identityNeed 证据等级分类错误

- **现象**：全部 5 案例 `deepNeeds.identityNeed` 被标记为 `confirmed_decision`，内容含"消费者可能希望""据其行为推测"等假设性语言
- **根因**：S4 extractor 将 `identityNeed` 归类为决策型字段，但实际是从观察推导的推断
- **影响**：降低 Decision Memory 中 confirmed_decision 分类的可靠性
- **优化建议**：S4 extractor 中 `identityNeed` 改为输出 `hypothesis`，或在内容出现"可能/推测"时自动降级

## P3 · 报告语体检测启发式过严

- **现象**：AI 开场白均为专业咨询报告语体，但 `detectReportStyle()` 检出率 0/40
- **根因**：detectReportStyle formalPatterns 要求精确匹配（如"数据显示""基于以上"），AI 实际使用不同但同样专业的表达（如"我们进入""前序阶段已确认""帮你理清"）
- **影响**：不影响功能，统计指标失真
- **优化建议**：
  1. 降低阈值：score >= 3 改为 >= 2
  2. 增加 AI 实际使用的模式词

## P3 · Founder 模拟器收束信号不够自然

- **现象**：部分阶段最后一轮 founder 的"可以进行收束了"过渡生硬
- **根因**：`isFinalRound` 指令强制插入收束信号，与对话上下文可能不连贯
- **影响**：轻微影响对话自然度
- **优化建议**：改为让 founder 根据对话自然程度主观判断是否可收束，而非固定触发
