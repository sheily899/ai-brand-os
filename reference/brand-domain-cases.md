# 品牌域技能内容质量测试集

> 每次修改域技能 prompt 后，重新跑一遍本测试集，人工核对记录不合格处。

---

## 测试方法

1. 启动 `npm run dev`，在浏览器中创建新项目
2. 按以下画像输入创始人信息，走完 S1→S8 全部流程
3. 每阶段完成后，对照 **验证标准** 逐项检查产出质量
4. 记录 ✅/❌ 和具体问题到对应画像的评估表

---

## 验证标准（从各阶段 prompt + Zod Schema 提取）

### Stage 1 · 用户访谈

| # | 标准 | 来源 |
|---|------|------|
| 1.1 | founderMotivation.content ≥ 10 字，来源为 founder_statement | Schema |
| 1.2 | observations ≥ 3 条，每条四要素（subject/context/behavior/result）完整 | Schema + Exit |
| 1.3 | constraints（budget/team/timeline）均已收集 | Exit |
| 1.4 | 创始人类型（problem_driven / creation_driven）已判断 | Schema |
| 1.5 | AI 的追问具体而非泛泛（"能具体描述一次观察到的行为吗"优于"还有其他问题吗"） | Prompt |
| 1.6 | AI 不使用二选一或多选一句式（"是 A 还是 B""更像 A 还是 B""是来自……还是……"），违规时自查并重写为开放式问题 | Prompt (stage1-consultation.md:71-82) |
| 1.7 | AI 通过开放问题判断创始人类型，不通过二选一确认（不在问题中预先摆出两个选项让创始人选） | Prompt (stage1-consultation.md:127-135) |
| 1.8 | 追问遵循三层递进规则（事实→原因→意义），同一话题不超过三层，不靠切换话题标签规避层数限制 | Prompt (stage1-consultation.md:97-112) |
| 1.9 | AI 不使用诱导句式：不预设痛点（"哪里让你不满意"→"有没有让你觉得还不够的地方"）、不预设心理（"你是不是觉得……"→"当时你的第一反应是什么"），给用户说"没有"的空间 | Prompt (stage1-consultation.md:84-95) |
| 1.10 | 用户明确否定后（"没有""没有这个愿望"等），AI 关闭该追问路径，不换角度重探同一件事 | Prompt (stage1-consultation.md:89-95) |

### Stage 2 · 商业背景分析

| # | 标准 | 来源 |
|---|------|------|
| 2.1 | marketContext ≥ 20 字，包含行业宏观背景与趋势判断 | Schema |
| 2.2 | drivingForces 2-5 个，每个是底层驱动因素而非表面现象 | Schema + Prompt |
| 2.3 | strategicWindow 说明"为什么是现在" | Schema + Exit |
| 2.4 | externalChallenges + internalChallenges 各≥1 个 | Schema |
| 2.5 | directionHypothesis ≥ 10 字，方向性假设明确 | Schema |
| 2.6 | 语言为专业分析语言（非口语），不含创始人原始语气 | Prompt |
| 2.7 | AI 不使用二选一或多选一句式（"是……还是……""是 A 还是 B"），违规时自查并重写为开放式问题 | Prompt (stage2-consultation.md:123-127) |

### Stage 3 · 市场机会分析

| # | 标准 | 来源 |
|---|------|------|
| 3.1 | categoryStatus.definition ≥ 20 字，包含品类边界和范围 | Schema |
| 3.2 | categoryStatus.trends ≥ 2 条，每条≥8 字 | Schema |
| 3.3 | experienceGaps ≥ 2 个，每个 gap≥15 字 + currentAlternative≥10 字 | Schema |
| 3.4 | opportunityDirections ≥ 1 个，每个含 direction + rationale + evidenceLevel | Schema |
| 3.5 | 机会方向包含证据可信度评级（verified/inferred/hypothesis） | Prompt + Schema |

### Stage 4 · 消费者洞察

| # | 标准 | 来源 |
|---|------|------|
| 4.1 | targetConsumer.definition ≥ 20 字，基于决策动机与行为特征 | Schema |
| 4.2 | idealSelfReflection ≥ 15 字 | Schema |
| 4.3 | existingSolutions ≥ 1 个，solutionType 为抽象行为路径（非产品名） | Schema + Prompt |
| 4.4 | failReason ≥ 12 字，包含"已满足什么 + 缺失什么 + 造成什么摩擦"三段式 | Schema + Prompt |
| 4.5 | functionalNeed + identityNeed 各≥15 字 | Schema |
| 4.6 | 消费者定义为专业分析语言，不是简单的人口标签 | Prompt |

### Stage 5 · 竞争判断

| # | 标准 | 来源 |
|---|------|------|
| 5.1 | competitiveLandscape.dimensions ≥ 2 个，每个≥4 字 | Schema |
| 5.2 | convergenceAndDivergence ≥ 15 字 | Schema |

| 5.4 | weakness ≥ 10 字，具体而非泛泛而谈 | Schema |

### Stage 6 · 品牌核心战略

| # | 标准 | 来源 |
|---|------|------|
| 6.1 | positioning ≥ 15 字，包含目标人群+品类框架+核心价值+选择理由 | Schema + Exit |
| 6.2 | valuePropositions 恰好 3 条（功能/情感/社会），每条含 soWhatDerivation | Schema |
| 6.3 | brandStory 三要素（struggleMoment/brandAction/brandRelationship）完整 | Schema + Exit |
| 6.4 | brandPersonality 5-7 个，每个含 dos/donts 行为描述 | Schema + Exit |
| 6.5 | 定位基于前序阶段发现，非凭空创造 | Prompt |

### Stage 7 · 视觉策略

| # | 标准 | 来源 |
|---|------|------|
| 7.1 | coreConcept ≥ 15 字，统领性视觉美学 | Schema + Exit |
| 7.2 | keywords 3-5 个，每个含 keyword + rationale | Schema + Exit |
| 7.3 | visualSystem 五种语言（form/color/typography/imagery/material）全部填充 | Schema + Exit |
| 7.4 | 每种语言含 choice（≥8字）+ exclusions（≥4字）+ perceptualTone（≥8字） | Schema |
| 7.5 | restrictions ≥ 3 个，每个含 exclusion + strategicRationale | Schema + Exit |
| 7.6 | 视觉方向与 S6 品牌人格一致（安静个性不配冲击视觉） | Prompt |

### Stage 8 · 内容规划

| # | 标准 | 来源 |
|---|------|------|
| 8.1 | coreDirection ≥ 15 字，承接品牌故事 | Schema |
| 8.2 | contentValueSystem 覆盖 4 阶段（awareness/interest/trust/decision） | Schema + Exit |
| 8.3 | themeDirections 2-4 个，每个含 pillar + corePurpose + topicDirections≥1 | Schema + Exit |
| 8.4 | channelStrategy 覆盖三大平台（小红书/抖音/微信） | Schema + Exit |
| 8.5 | 内容策略可追溯到 S6 品牌故事 | Prompt |
| 8.6 | 不包含 `*` `**` markdown 符号 | 用户反馈 |
