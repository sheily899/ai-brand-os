# 机会 3 前置分析：对话历史滚动摘要

> 分析时间：2026-08-05 | 结论：跳过

---

## 一、分析目标

验证"对话历史滚动摘要（Rolling Summary）"是否为真实 Token 瓶颈。

判定标准：如果 conversation history 平均占比 > 30% 总 input，则推进对比实验；否则跳过。

## 三、判定

**跳过机会 3。**

原因：
- 对话历史仅占总 input 的 5.4%，远低于 30% 阈值
- 最高单阶段 S1 也只有 12.3%
- 即便把历史全部压缩到零，最多省 515 tokens/次
- 滚动摘要本身引入的 LLM 调用成本和摘要质量风险，远超这点收益
- System Prompt（88.3%）才是主体，而机会 1（DM 分层）和机会 2（Search Context 压缩）已经覆盖了其中最大的可变部分

## 五、经验教训

这是一个典型案例：**"看起来高级但实际收益低"的优化方向。**

机会 3 在直觉上合理——对话越长，历史越膨胀，滚动摘要是自然的解决方案。但真实数据显示：
- 品牌咨询对话天然精简（每阶段 4-6 轮），用户不会无限制地聊下去
- System Prompt（含 DM + Search + 模板）是绝对 Token 消费者，对话历史微不足道
- 用数据说话比凭直觉做优化更可靠

**教训：任何 Token 优化方向，必须先用真实调用数据证明它是瓶颈，再做优化。**
